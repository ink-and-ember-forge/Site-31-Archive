# Site 31 Archive

An episodic digital anthology told through an archive. Each episode is a **case file**: a
folder the reader opens onto a virtual work table of documents they can move, zoom into and
interrogate. See [`docs/design-document.md`](docs/design-document.md) for the vision and
[`CLAUDE.md`](CLAUDE.md) for the build instructions.

> **Status:** the package format (v1) is agreed and implemented, with validation and an automatic archive
> build. The authoring tool is being built in steps (step 1 of 5 is in; see `docs/authoring-tool-v0.md`).

## Layout

| Path | What it is |
| --- | --- |
| `apps/viewer` | The reader's viewer: Vite + TypeScript + Svelte, deployed to GitHub Pages |
| `apps/author` | The authoring tool: Electron desktop app. Installers are attached to each GitHub Release |
| `packages/casefile` | The case file package contract (format, types, validator), shared by both. The package contract: schemas, validator, loader and archive build |
| `episodes/` | Case file packages, one folder per episode |
| `docs/` | Design document, package format spec, and [how to write an episode](docs/writing-an-episode.md) |
| `theme/` | Shared templates, styles and assets (look and feel as data) |
| `DECISIONS.md` | Decisions with dates and reasons |
| `CHANGELOG.md` | Generated by release-please. Do not edit |

## Run

Requires Node 22 (`nvm use` reads `.nvmrc`).

```bash
npm install
```

```bash
npm run dev:viewer
```

That starts the live preview described in [writing an episode](docs/writing-an-episode.md).

```bash
npm run dev:author
```

Checks, as run in CI:

```bash
npm run check && npm test && npm run build
```

## Build and deploy (automatic)

There is no manual build step.

- **Pull requests:** CI type-checks, tests and builds everything. The PR title must follow
  [Conventional Commits](https://www.conventionalcommits.org/) (e.g. `feat(viewer): folder wall`).
- **Merge to `main`:** the viewer is built and published to GitHub Pages at
  `https://ink-and-ember-forge.github.io/Site-31-Archive/`.
- **Releases:** release-please keeps a release PR open. Merging it updates `CHANGELOG.md`,
  bumps the version, tags a release and attaches authoring-tool installers (macOS, Windows,
  Linux) to it.

Use **squash merge** so the PR title becomes the commit message.

## Add an episode

The full walkthrough for writers is [`docs/writing-an-episode.md`](docs/writing-an-episode.md). In short:

1. Copy [`packages/casefile/fixtures/valid/sample-placeholder`](packages/casefile/fixtures/valid/sample-placeholder)
   to `episodes/<episode-id>/` (lowercase, hyphens; it must match `id` in `case.json`) and replace the placeholder content.
2. Run `npm run dev:viewer` for a live preview. Saving any file in `episodes/` or `theme/` rebuilds the archive and
   refreshes the browser, and mistakes appear as a readable message over the page.
3. Run `npm run validate` for a plain-English check of every episode (or `npm run validate -- <episode-id>`).
4. Merge. The build validates the folder, zips it to a `.casefile`, regenerates the archive index and redeploys.
   There is no index to edit and no code to change.

An invalid episode fails the build with a message naming the file. Content problems that don't stop an
episode opening (a missing image, a bad hotspot) are printed as warnings and degraded gracefully.

New document looks and layouts are data: add templates and styles to `theme/` (see `theme/README.md`).

The clearly labelled placeholder sample is shown only while `episodes/` is empty; the first real episode replaces it
automatically.

## One-time GitHub settings (cannot be set from code)

1. **Settings → Pages → Source: GitHub Actions.**
2. **Settings → Actions → General → Workflow permissions:** allow Actions to create and
   approve pull requests (needed by release-please).
3. **Settings → General → Pull Requests:** enable squash merging, default to PR title.
4. Optional: protect `main` and require the `CI / verify` and `PR title` checks.
